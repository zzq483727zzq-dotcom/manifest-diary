# Clarity · 个人健康与状态管理系统 — 产品重定位设计

> 日期：2026-07-25  
> 状态：已确认，待实施  
> 目标：将现有「显化日记 / 生活管理系统」重定位为可写进简历的**个人健康与状态管理系统**；主线实用、可演示、前后端能力清晰。

---

## 一、背景与决策

### 1.1 现状问题

当前仓库混有两代产品叙事：

| 阶段 | 定位 | 代表能力 |
|---|---|---|
| v1 | 显化日记 / 复盘陪伴 | 显化、见证、复盘「哥」人格、晨间脚本 |
| 近期 | 生活管理系统 | 睡眠 / 专注 / 能量 / 运动记录、仪表盘、趋势、AI 洞察 |

结果是：系统外壳像「管理系统」，但主线不统一，简历与演示都不好讲。

### 1.2 决策

- **不做**：继续以复盘 / 显化 / 情感陪伴为主产品  
- **要做**：实用的**个人健康与状态管理系统**（方案 A 的健康向）  
- **用途**：个人可用 + 简历项目（前端 / 全栈）  
- **策略**：换业务主线与信息架构，尽量复用现有 `life_logs`、仪表盘、本地解锁、API，而不是从零重写

### 1.3 产品一句话

**Clarity · 个人健康与状态管理系统**  
记录睡眠、运动、能量/心情与基础习惯，用健康仪表盘看今日状态与趋势，可选 AI 健康洞察；数据默认本地私密存储。

### 1.4 简历一句话（可用）

> 基于 Next.js 的个人健康与状态管理系统：支持睡眠 / 运动 / 能量等多维记录、健康趋势看板、本地加密解锁与可选 AI 洞察；覆盖仪表盘、表单 CRUD、统计 API 与 SQLite 本地持久化。

## 二、用户与成功标准

### 2.1 用户

- 主要用户：开发者本人（自用 + 演示）  
- 同类用户：想用简单数据看清「睡够没、动了没、状态稳不稳」的个人

### 2.2 成功标准（P0 验收）

1. 解锁后进入健康向首页，主导航无显化 / 复盘主入口  
2. 首页展示：睡眠、运动、能量、今日记录完成度  
3. 可稳定录入睡眠 / 运动 / 能量三类记录  
4. 近 7 日趋势可读；无数据时有可操作空态  
5. 演示路径完整：解锁 → 首页 → 记录 → 回首页数字更新  
6. AI 洞察失败不影响记录与图表  
7. 文案统一为「健康 / 状态 / 记录 / 趋势」，无医疗诊断表述

### 2.3 非目标（本轮明确不做）

- 医疗诊断、处方、穿戴设备同步  
- 多人协作、复杂 RBAC、社交  
- 继续把显化 / 见证 / 情感复盘作为主流程  
- 完整目标 / 项目管理系统（那是另一产品方向）  
- 本轮不要求重做视觉体系（沿用现有 UI，只改信息与文案）

## 三、核心闭环与指标

### 3.1 演示主路径

```text
解锁进入
  → 看今日健康指标（睡眠 / 运动 / 能量 / 完成度）
  → 快速记一条（睡眠时长 / 运动时长 / 能量分）
  → 看近 7 天健康趋势
  →（可选）看 AI 健康简报
```

### 3.2 指标优先级

| 优先级 | 指标 | 数据来源 | 说明 |
|---|---|---|---|
| P0 | 睡眠 | `life_logs.type = sleep` | 时长（小时）；可选质量分进 metadata |
| P0 | 运动 | `life_logs.type = exercise` | 时长（分钟）；可选类型（步行/有氧/力量）进 metadata |
| P0 | 能量 / 身心状态 | `life_logs.type = mood` | 1–10 分（本轮不新增 `energy` 类型，避免迁移成本） |
| P0 | 今日记录完成度 | 当日是否覆盖关键类型 | 默认关键：sleep / exercise / mood |
| P1 | 习惯打卡 | 后续扩展 | 喝水、拉伸等；本轮可不做 |
| P2 | 专注 | `life_logs.type = focus` | 可从记录页录入，不占首页主位、不进主导航主叙事 |

## 四、信息架构与页面

### 4.1 主导航（登录后）

| 路由 | 名称 | 作用 |
|---|---|---|
| `/` | 今日 | 健康仪表盘：四指标 + 7 日趋势 + 快捷记录 + 可选洞察 |
| `/log` | 记录 | 统一录入入口（睡眠、运动、能量；可选 focus/journal） |
| `/sleep` | 睡眠 | 睡眠详情与历史（若已有页面则改文案与数据展示） |
| `/insights` | 洞察 | AI 健康简报；无 key / 失败时友好空态 |
| `/timeline` | 时间线 | 按日浏览健康记录 |
| `/history` | 日历 | 月历查看哪天有记录 |

运动若暂无独立路由：P0 放在 `/log` + 首页卡片即可；P1 再拆 `/exercise`。

### 4.2 从主导航隐藏（代码可保留，不进主产品）

| 路由 / 能力 | 原用途 | 处理 |
|---|---|---|
| `/manifest` | 显化 | 隐藏出主导航 |
| `/reflect` | 复盘 | 隐藏出主导航 |
| `/focus` | 专注 | 降级：记录类型可选，不单独占主位 |
| 见证日 / 见证卡片 | 仪式闭环 | 隐藏；API 可保留不删 |

### 4.3 系统页（保留）

| 路由 | 作用 |
|---|---|
| `/setup` | 首次设置本地密码 |
| `/unlock` | 解锁进入 |
| `/login` | 兼容入口，可重定向到 unlock |

### 4.4 首页信息架构

```text
顶部：今日日期 + 问候（健康语境）
卡片行：睡眠时长 | 运动时长 | 能量分 | 今日记录完成度
中部：近 7 日趋势（睡眠 / 运动 / 能量）
下部：快捷记录 + 最近记录 +（可选）AI 健康洞察
```

### 4.5 文案基调

- 使用：健康、状态、记录、趋势、简报  
- 不使用主叙事：显化、见证、复盘、「哥」  
- AI：描述性状态简报；不诊断、不恐吓、不宣称医疗结论

## 五、数据模型与 API

### 5.1 数据模型（复用 `life_logs`）

沿用现有类型与字段，不强制本轮改表：

- `type`: `sleep | focus | mood | exercise | journal | manifest`  
- `entry_date`, `start_at`, `end_at`, `value`, `unit`, `content`, `metadata`

**首页映射**

| 展示 | 聚合规则 |
|---|---|
| 睡眠 | 当日 `sleep` 的 `value`（hours）汇总或主记录 |
| 运动 | 当日 `exercise` 的 `value`（minutes）汇总 |
| 能量 | 当日 `mood` 的 `value`（score）；多条可取均值或最新（实现时固定一种并写清） |
| 完成度 | 关键类型中当日已有记录的比例 |

`metadata` 建议约定（非强制迁移）：

- 睡眠：`{ quality?: number }`  
- 运动：`{ kind?: 'walk' | 'cardio' | 'strength' | 'other' }`

### 5.2 API 边界

| 能力 | 说明 |
|---|---|
| Life log CRUD | 列表 / 新增 / 更新 / 删除 |
| 今日汇总 | 睡眠、运动、能量、完成度 |
| 趋势 | 近 7 / 30 日聚合点 |
| 洞察 | 可选 AI：输入近期数据 → 短文案；失败可降级 |
| 鉴权 | 本地密码解锁会话；云端路径保持 user 隔离 |

原则：

1. 统计在服务端或统一 lib 计算，前端只展示  
2. AI 非阻塞：记录与图表不依赖 AI 成功  
3. 本地 SQLite 为默认演示路径；Supabase 为可选加分项  

### 5.3 与旧能力的关系

- 显化 / 复盘 / 见证：**不删库表与路由文件亦可**，但产品层隐藏  
- `manifest` 类型：可不在健康统计中计入完成度  
- 旧设计文档保留作历史；**本文件为当前产品主规格**

## 七、简历与演示

### 7.1 可写技术点

**前端**

- Next.js App Router 多页面与仪表盘组件  
- 表单录入、趋势图、加载 / 空态 / 错误态  
- 本地解锁门禁交互

- 可选 LLM 洞察与失败降级

1. 打开站点 → 解锁  
2. 首页展示今日健康卡片与趋势

4. 回首页确认数字更新  
5. （可选）打开洞察  
6. 收束：本地私密 + 统计 API + 全栈结构  

### 7.3 项目命名

- 对外产品名：**Clarity · 个人健康与状态管理系统**  
- 仓库名可暂不改，避免无关成本；README / 演示文案使用新定位
