# Clarity 执行复盘扩展设计

日期：2026-07-31
状态：已确认，待实现计划

## 目标

在现有本地优先的 Clarity 项目执行系统上，增加依赖/阻塞管理和执行复盘能力，让用户能够回答两件事：

1. 当前任务为什么不能推进，以及下一步是否可以开始。
2. 一段时间内时间花在哪里，计划与实际相差多少，哪些项目或任务经常拖延。

实现按“数据基础 → 执行流程 → 今日台复盘 → 可视化 → 拖延分析”分阶段推进。首轮实现聚焦前四层，拖延分析建立在新增历史数据之上。

## 已确定的产品规则

### 专注与状态

- `target_minutes` 是一次专注倒计时目标，默认 25 分钟。
- `estimate_minutes` 是任务预计总投入，用于预计/实际偏差，默认 25 分钟；与 `target_minutes` 独立。
- 开始专注时，任务从待办进入进行中。
- 暂停只暂停专注，不完成任务。
- 倒计时归零时保存任务专注记录并将任务标记为已完成。
- 提前结束保存已专注时间并将任务标记为已完成。
- 手动标记完成时自动停止运行中的计时并保存累计时间。
- 已完成任务不能再次开始专注。

### 依赖

- 依赖只允许来自同一项目。
- 任务不能依赖自己。
- 添加依赖时必须拒绝循环依赖。
- 一个任务可以有多个前置任务。
- `all` 模式要求所有前置任务完成。
- `any` 模式要求任意一个前置任务完成。
- 默认模式为 `all`。
- 删除任务时删除相关依赖和依赖例外记录。
- 已归档项目中的依赖关系保留，但不可编辑。

### 阻塞

任务支持两种阻塞来源：

- 等待前置任务：由未完成依赖自动产生。
- 外部阻塞：用户手动开启并填写原因，例如等待资料、反馈或他人确认。

两种阻塞可以同时存在。只要存在任意一种阻塞，普通“开始专注”就会被拦截。用户可以主动确认“仍然开始”绕过依赖；绕过行为必须写入依赖例外记录。外部阻塞同样需要明确确认才能绕过。

## 数据模型

### Task 扩展

- `estimate_minutes: number`：预计总投入，默认 25。
- `dependency_mode: 'all' | 'any'`：依赖完成规则，默认 `all`。
- `is_blocked: boolean`：是否存在手动外部阻塞，默认 `false`。
- `blocked_reason: string | null`：外部阻塞原因。
- `blocked_at: string | null`：最近一次开启外部阻塞的时间。

现有字段继续保留：

- `target_minutes`：单次倒计时目标。
- `started_at`、`elapsed_seconds`：计时运行态。
- `completed_at`：完成时间。

### TaskDependency

```ts
interface TaskDependency {
  id: string;
  task_id: string;
  depends_on_task_id: string;
  created_at: string;
}
```

`task_id` 是被阻塞的任务，`depends_on_task_id` 是前置任务。

### DependencyBypass

```ts
interface DependencyBypass {
  id: string;
  task_id: string;
  dependency_ids: string[];
  reason: string;
  created_at: string;
}
```

`dependency_ids` 保存绕过时未完成的前置任务依赖记录。若绕过的是外部阻塞，使用空数组并在 `reason` 中保留用户确认原因。

### ClarityDB

在现有数据库信封中新增：

- `taskDependencies: TaskDependency[]`
- `dependencyBypasses: DependencyBypass[]`

老 localStorage 数据和旧 JSON 备份缺少这些字段时，统一补为空数组；任务新增字段补默认值。

## 仓库接口

新增纯函数和变更函数：

- `listTaskDependencies(db, taskId)`
- `addTaskDependency(db, taskId, dependsOnTaskId)`
- `removeTaskDependency(db, dependencyId)`
- `canTaskStart(db, taskId)`
- `getTaskBlockers(db, taskId)`
- `setTaskBlocked(db, taskId, reason)`
- `clearTaskBlocked(db, taskId)`
- `recordDependencyBypass(db, taskId, dependencyIds, reason)`
- `completeTaskFromTimer(db, taskId, note)`

`canTaskStart` 返回可执行状态、阻塞类型、阻塞原因和未完成前置任务，供任务卡、任务详情和今日台复用。循环检测使用 DFS 或等价的图遍历；不能只依赖 UI 校验。

开始专注的统一流程：

```text
请求开始
  -> 读取任务阻塞信息
  -> 无阻塞：任务进入 in_progress，启动计时
  -> 有阻塞：返回阻塞原因，不改变状态
  -> 用户确认绕过：写入 DependencyBypass，任务进入 in_progress，启动计时
```

## 今日台与复盘

现有今日台行动区继续保持第一优先级，复盘区位于其下方并使用一列纵向布局。

### 范围

默认范围为本周一到今天，支持：

- 今天
- 本周
- 本月
- 自定义开始日期和结束日期

范围切换同步刷新所有指标、图表和详情。桌面端详情默认展开，移动端默认折叠；用户的展开状态保存在 localStorage。

### 统计口径

- 任务投入：`TimeEntry`。
- 项目整体投入：`ProjectTimeEntry`。
- 总投入：任务投入 + 项目整体投入。
- 今日台已有“本周投入”继续只显示任务投入。
- 预计偏差：任务预计总投入与实际任务专注的差值。
- 完成周期：任务创建时间到完成时间。
- 逾期数量：截止日期早于完成时间或统计范围结束时间的任务。
- 阻塞数量：统计范围内出现过外部阻塞或依赖阻塞的任务。

### 视觉结构

- 范围切换条。
- 摘要指标：任务专注、项目专注、总投入、完成、逾期、阻塞。
- 每日投入趋势：任务/项目投入柱状图，总投入折线。
- 项目投入横向排行：显示任务投入、项目投入和总投入。
- 执行复盘详情：预计/实际偏差、完成周期、逾期、依赖阻塞、外部阻塞、依赖绕过。

图表必须提供悬停明细和对应表格视图；颜色用于区分固定实体，不随排序或筛选重新分配。趋势图保持单纵轴，不使用双轴。

## 前端交互

### 任务卡

- 显示预计时长、专注累计和依赖进度。
- 显示“等待前置任务”“外部阻塞”“已绕过依赖”等状态。
- 开始专注按钮在无阻塞时直接启动。
- 有阻塞时弹出确认，展示阻塞原因和“仍然开始”。
- 运行中按钮为暂停。
- 运行中或有累计时间时显示“提前结束”。

### 任务详情

增加“执行条件”区域：

- 添加/删除同项目的前置任务。
- 切换 `all` / `any` 模式。
- 开启/解除外部阻塞并编辑原因。
- 查看依赖例外记录。

保留任务倒计时设置和完整控制。提前结束与暂停明确区分：暂停可继续，提前结束会完成任务。

## 错误处理与兼容

- 所有新数据在 `loadDB` 和 `importBackup` 中归一化。
- 跨项目依赖、自依赖、循环依赖、归档项目编辑必须在仓库层抛出明确错误。
- 删除任务必须清理依赖和依赖例外，避免悬空引用。
- 计时落账失败不能重复写入；完成动作不能留下运行中的 `started_at`。
- 静态导出继续只使用 localStorage，不增加服务端依赖。

## 测试计划

### 仓库与数据

- 旧数据默认字段归一化。
- 创建任务保存预计时长。
- 同项目依赖可以添加和删除。
- 跨项目、自依赖和循环依赖被拒绝。
- `all` / `any` 可执行判断正确。
- 外部阻塞可以开启、解除并保留原因。
- 删除任务清理依赖和依赖例外。
- 项目整体投入不进入任务投入统计。

### 计时与状态

- 开始专注自动进入进行中。
- 暂停保持进行中。
- 倒计时归零自动记录并完成任务。
- 提前结束自动记录并完成任务。
- 手动完成运行中任务自动记录。
- 完成后不能重新开始。
- 阻塞时普通开始被拦截。
- 绕过阻塞后记录例外并开始。

### 今日台

- 今天、本周、本月、自定义范围计算正确。
- 任务和项目投入分开显示，总投入正确。
- 预计/实际偏差和完成周期正确。
- 逾期、阻塞、依赖绕过详情正确。
- 趋势图和项目排行与表格视图数据一致。
- 桌面展开、移动折叠和本地展开状态正确保存。

## 分阶段交付

1. 数据字段、依赖图和阻塞仓库接口。
2. 任务卡/详情依赖管理、开始拦截和状态自动流转。
3. 今日台范围切换、摘要指标和详情复盘。
4. 趋势图、项目排行、悬停和表格视图。
5. 拖延分析、完成周期趋势和项目停滞提示。

每一阶段都必须通过类型检查、单元测试、静态构建和浏览器 smoke test 后再进入下一阶段。
