# Clarity · 个人项目执行系统设计规格

> 日期：2026-07-28  
> 状态：待用户审阅  
> 目标：将现有健康 / 显化 / 复盘产品彻底重定位为本地优先的**个人项目执行系统**，支持项目、任务、子任务、耗时记录、今日行动台、月/周日历与 JSON 备份。

---

## 一、产品定位

### 1.1 一句话

**Clarity · 个人项目执行系统**  
帮助个人把有限的项目持续推进到完成：任务必须归属项目，首页聚焦逾期、今日到期与进行中任务，并用截止日期、进度和耗时记录支撑执行。

### 1.2 用户

- 主要用户：开发者本人
- 使用场景：作品集、学习计划、求职准备、长期副项目等个人项目推进
- 次要目标：作为前后端 / 全栈简历项目演示

### 1.3 核心差异

它不是 Todo 堆积工具，也不是健康记录工具。

```text
所有任务必须归属项目
→ 首页只强调需要推进的任务
→ 用项目进度、截止日期和耗时帮助持续推进
→ 避免无限待办清单
```

### 1.4 成功标准（P0）

1. 设置 / 解锁本地密码  
2. 创建第一个项目  
3. 创建多个任务  
4. 设置优先级、截止日期、子任务  
5. 完成任务并记录耗时  
6. 首页显示行动分组、项目进度、本周投入  
7. 日历支持月视图和周视图  
8. JSON 导出 / 导入可恢复数据  
9. 未解锁不能访问业务页和 API  
10. 删除任务会清理子任务和耗时  
11. 项目进度与累计耗时正确  
12. 浅色现代工作台在桌面和移动端可用

## 四、核心对象与规则

### 4.1 项目

字段：

```text
id                UUID
name              1–80 字符，必填，允许重名
description       0–2000 字符，可选
color             6 个固定色之一，默认青绿
target_date       YYYY-MM-DD，可选
status            active | completed | archived
created_at
updated_at
completed_at      可空
```

项目状态：

```text
active      进行中
completed   已完成
archived    已归档
```

项目规则：

- 允许空项目
- 进度 = 已完成任务数 / 全部任务数
- 无任务时进度 0%
- 最近截止日期 = 未完成任务中最早的截止日期
- 目标日期只做项目级提醒，不自动改任务
- 项目由用户手动完成；若仍有未完成任务，二次确认
- 完成项目不自动改任务状态
- 已完成可重新打开；已归档可取消归档
- 项目不能直接删除，只能归档
- 项目列表默认显示进行中，可筛：进行中 / 全部 / 已完成 / 已归档
- 排序：最近更新在前；更新来源包括项目、任务、子任务、耗时变化

项目颜色：

```text
青绿 #5EEAD4
天蓝 #7DD3FC
紫色 #C4B5FD
金色 #FBBF24
珊瑚 #FB7185
绿色 #86EFAC
```

### 4.2 任务

字段：

```text
id                UUID
project_id        UUID，必填
title             1–120 字符，必填，允许重名
description       0–5000 字符，可选，纯文本
status            todo | in_progress | completed
priority          low | medium | high，默认 medium
due_date          YYYY-MM-DD，可选，仅日期
position          number，用于同列手动排序
created_at
updated_at
completed_at      可空
```

任务状态：

```text
todo          待办
in_progress   进行中
completed     已完成
```

任务规则：

- 必须归属项目
- 不允许收件箱任务
- 可在进行中 / 已完成项目之间移动
- 不能移动到已归档项目
- 完成时写 `completed_at`
- 重新打开时清空 `completed_at`
- 再次完成写新的完成时间
- 删除前二次确认
- 删除时级联删除子任务和耗时记录
- 完成后保留历史；看板“已完成”列默认显示最近 5 条，可展开

优先级显示：

```text
高：珊瑚色小点 + 文字
中：金色小点 + 文字
低：灰蓝色小点 + 文字
```

### 4.3 子任务

字段：

```text
id            UUID
task_id       UUID
title         1–120 字符，必填
is_done       boolean
position      number
created_at
updated_at
```

规则：

- 轻量：只有标题、完成状态、排序
- 不支持描述、优先级、截止日期、耗时
- 单任务最多 20 个
- 新建追加到末尾
- 支持上移 / 下移
- 完成不自动沉底
- 父任务完成时若仍有未完成子任务，二次确认
- 父任务完成后，子任务状态保持原样
- 父任务重新打开时，不重置子任务

### 4.4 耗时记录

字段：

```text
id            UUID
task_id       UUID
minutes       1–1440 正整数
logged_date   YYYY-MM-DD，默认今天，不可晚于今天
note          0–200 字符，可选
created_at
updated_at
```

规则：

- 必须归属任务，不能直接挂项目
- 子任务不能记时
- 待办 / 进行中 / 已完成任务都可补录
- 已归档项目中的任务只读
- 支持编辑和确认删除
- 任务累计耗时 = 其 time_entries 求和
- 项目累计耗时 = 项目下全部任务耗时求和
- 本周投入按 `logged_date` 统计，周一到周日
- 修改日期后统计自动归入对应周

展示位置：

```text
任务详情：记录列表 + 累计
项目详情：项目累计 + 各任务汇总
今日首页：本周总投入
看板卡片：不显示耗时
```

## 五、页面规格

### 5.1 今日行动台 `/`

首页是行动台，不是数据大屏。

任务分组，每组最多 5 条：

```text
1. 已逾期
2. 今天到期
3. 未来 3 天内的高优先级任务
4. 进行中任务
```

排序规则：

```text
1. 已逾期且高优先级
2. 今天到期
3. 未来 3 天高优先级
4. 进行中项目里的进行中任务
5. 其他待办
```

同一任务只进入最紧急的一组。  
已完成任务不出现。  
超过 5 条显示“查看全部”。

任务卡片字段：

```text
标题
所属项目
优先级
截止日期 / 逾期天数
状态
```

点击任务：

```text
/projects/[projectId]?task=[taskId]
→ 打开项目页并自动打开任务抽屉
```

轻量统计：

```text
本周完成任务数
进行中项目数
本周完成率 = 本周到期且已完成 / 本周到期
本周投入时长
```

本周完成率分母为 0 时显示 `—`，不显示 100%。

项目概览：

```text
进行中项目卡片
完成数 / 总数 · 百分比
累计耗时
最近截止日期
```

导航角标：

```text
今日角标 = 逾期未完成 + 今天到期未完成
```

空状态：

```text
今天没有需要处理的任务
可以继续推进一个项目，或者先创建下一步任务。
[查看项目]
```

### 5.2 项目列表 `/projects`

- 默认筛选：进行中
- 可筛：进行中 / 全部 / 已完成 / 已归档
- 不做搜索
- 不做置顶
- 按最近更新排序

项目卡片：

```text
项目名称
状态
进度：6 / 12（50%）
最近截止日期
项目颜色标识
```

创建项目：

- 右侧抽屉，移动端全屏
- 字段：名称 / 描述 / 颜色 / 目标日期
- 创建成功后进入项目详情

首次无项目空状态：

```text
还没有进行中的项目
把一个想完成的事情变成可执行的项目。
[创建第一个项目]
```

### 5.3 项目详情 `/projects/[id]`

顶部：

```text
项目名称
状态
描述
目标日期
完成进度
累计耗时
看板 / 列表切换
新建任务
项目设置菜单：编辑 / 完成 / 重新打开 / 归档 / 取消归档
```

默认视图：看板  
记住最近一次视图偏好，保存在本地设置，不按项目分别记。

#### 看板

列：

```text
待办 | 进行中 | 已完成
```

- 不做拖拽
- 卡片完成勾选可直接完成 / 重新打开
- 点击标题打开详情抽屉
- 同列排序：优先级 → 有截止日期 → 截止日期近 → 创建时间 → position
- 支持上移 / 下移调整 position
- 已完成列默认最近 5 条，可展开

#### 列表

列：

```text
完成勾选
标题
优先级
截止日期
状态
累计耗时
操作
```

筛选：

```text
全部 / 未完成 / 已完成
```

排序：

```text
优先级 / 截止日期 / 创建时间
```

### 5.4 任务详情抽屉

结构：

```text
标题
项目归属 / 状态 / 优先级 / 截止日期
描述
子任务
耗时记录
删除任务
```

保存规则：

- 普通字段统一点击保存
- 状态切换、子任务勾选即时保存
- 未保存关闭时提示确认放弃
- 保存失败保留内容并提示错误

新建任务默认：

```text
状态：todo
优先级：medium
位置：待办列顶部
创建成功后打开详情抽屉
```

首页快速新建任务：

- 必须选择项目

### 5.5 日历 `/calendar`

两种视图：

```text
月视图（默认）
周视图
```

共享规则：

- 按任务截止日期展示
- 无截止日期任务不进入日历
- 未完成：项目颜色标识
- 已完成：弱化并显示完成状态
- 逾期：红色强调
- 过滤：全部 / 仅未完成，默认全部，月周共享
- 一周从周一开始
- URL 保留 year / month / view
- 非法参数回退当前月 / 当前周

点击日期：

```text
桌面：右侧当日任务列表
移动：底部当日任务抽屉
点击任务：跳转项目页并打开任务详情
```

周视图：

```text
周一到周日分列
每天最多 4 条任务卡
超出显示“还有 N 项”
```

### 5.6 设置

入口：侧栏底部用户菜单。

功能：

```text
导出 JSON
导入 JSON
修改本地密码
```

修改密码：

```text
验证旧密码
新密码至少 6 位
确认两次新密码
更新后保持当前会话
```

## 六、数据与安全

### 6.1 存储

本地优先：

```text
SQLite + 本地密码解锁
```

不做云同步、注册登录、多设备同步。

### 6.2 迁移策略

一次性清理旧业务：

保留：

```text
app_settings
sessions
```

删除：

```text
旧健康数据与相关表
显化 / 复盘 / 见证数据与相关表
相关页面、API、组件、测试
```

新建：

```text
projects
tasks
subtasks
time_entries
```

正式执行迁移前需再次确认，因为会删除本地旧业务数据。

### 6.3 安全边界

```text
未设置密码 → /setup
已设置未解锁 → /unlock
已解锁 → 业务页面与 API
未解锁访问业务页 → 重定向 /unlock
未解锁调用业务 API → 401
```

### 6.4 备份

导出：

```json
{
  "version": 1,
  "exportedAt": "...",
  "projects": [],
  "tasks": [],
  "subtasks": [],
  "timeEntries": []
}
```

不导出密码和会话。

导入：

```text
校验 version 与结构
预览新增 / 更新数量
相同 UUID 更新
新 UUID 新增
本地多余数据保留
事务失败整体回滚
```

## 七、交互与反馈

### 7.1 快捷键

```text
N：当前页新建项目 / 新建任务
Esc：关闭抽屉
Enter：保存当前表单
```

### 7.2 错误

```text
字段错误：输入框下方内联
保存 / 网络错误：全局轻提示，保留输入
删除失败：轻提示，不关闭确认框
导入失败：面板内详细原因
```

### 7.3 成功

```text
状态切换 / 子任务勾选：静默
保存 / 创建 / 删除：轻提示
导入：面板摘要
导出：下载文件
```

### 7.4 加载

```text
页面首次：骨架屏
抽屉内容：局部 loading
写操作：按钮 loading 防重复
列表刷新：尽量保留旧数据
```

### 7.5 文案语气

直接、安静、有一点推动感。  
不用夸张激励或营销话术。  
每个空状态提供下一步操作。

## 八、视觉方向

### 8.1 Design Read

个人长期使用的项目执行工具，Operate 型界面。视觉走**浅色现代专业工作台**：干净、克制、偏 Linear / Arc / Notion 的高级产品感，不是深色终端风，也不是健康数据台或营销落地页。

### 8.2 视觉规则

```text
浅色纸白 / 雾灰背景
近黑文字（off-black，不是纯黑）
单一系统强调色：冷青绿 / 深青绿
大量留白与细分割线，少阴影
项目色只用于项目标识、任务左边线、日历色点
优先级用小色点 + 文字，不铺大面积色块
卡片轻量：细边框 + 轻微阴影，不做玻璃拟态堆叠
圆角统一、克制（约 10–14px）
```

### 8.3 主题

第一版只做**浅色主题**，不做深浅切换，也不跟随系统主题。

### 8.4 气质关键词

```text
现代
干净
安静
高级
可长时间工作
```

避免：

```text
霓虹强调色
大面积渐变
重玻璃拟态
深色仪表盘氛围
夸张动效
```

## 九、技术边界

### 9.1 技术栈

- Next.js App Router
- React
- TypeScript
- 本地 SQLite
- 本地密码会话
- Vitest

### 9.2 API 原则

- 业务 API 必须校验本地会话
- 统计在服务端 / 统一 lib 计算
- 写操作具备校验与明确错误
- 删除使用事务保证级联一致

### 9.3 日期规则

- 使用设备本地时区
- 截止日期 / 耗时日期保存 `YYYY-MM-DD`
- 创建 / 完成时间保存 ISO 时间戳
- “今天 / 逾期 / 本周”按本地日期判断
- 一周从周一开始
